# Keeper of the Cycle — working on the Godot port

The game is developed **by prompts, without the Godot editor**. Everything is
plain text (GDScript, JSON, level text). Every push builds the game for the
web and deploys it to GitHub Pages, so changes are tested in a browser.

## Layout

```
godot/                     Godot 4.4.1 project (GL Compatibility, 1066×600)
  project.godot            minimal engine config (autoloads, window)
  scenes/main.tscn         the only real scene — everything else is built in code
  scripts/main.gd          game flow / state machine (boot → title → forest → cave → boss → forest run → jackpot climb)
  scripts/autoload/        Game (state + input actions), Text (strings, dialogs, fonts), Audio
  scripts/screens/         boot, title, forest_intro, platformer (cave + boss; jackpot climb; old meadow; old summit + LH wave),
                           forest_runner (level 2: the forest run, map data/levels/forest_run.txt)
  scripts/minigames/       breathing, choco_puzzle (mg2), pipes (mg3), prices (mg4),
                           iron_plate (mg5), rhythm (mg6), signals (mg7) — level 2
  scripts/ui/              dialog_box, platformer_hud, player_art (sprite anim), draw helpers
  scripts/dev/             dev_menu + level_editor (in-game, DEV button on the first/boot screen)
  scripts/level_data.gd    level text → platforms/entities (THE LEGEND lives here)
  data/levels/cave.txt     the cave level, one text row per 120 px band, 25 columns
  data/levels/climb.txt    level 3, the jackpot climb (id 5; upwards: spawn at the bottom, E at the top;
                           generated by tools/gen_climb.py)
  data/levels/garden.txt   the old summit (id 3, dev menu only; climbed upwards)
  docs/                    GDD drafts (gdd_levely_fazy_cyklu.md = level 2 design, implemented)
  data/dialogs.json        dialog nodes (parts, speaker, buttons), voice overrides
  data/i18n/{en,sk,pt}.json  all strings; <KB>…</KB> keyboard-only, <GP>…</GP> gamepad-only
  assets/                  images, audio, font (from the web prototype)
  tests/test_runner.gd     headless end-to-end test — plays the whole game
web-export/                the original vibe-coded web build (reference only — do not edit)
tools/                     setup_godot.sh, test.sh, export_web.sh, gen_climb.py (generates climb.txt)
.github/workflows/web.yml  test → export → deploy to GitHub Pages (site/ + site/original/)
```

## Common edits

- **Level**: edit `godot/data/levels/cave.txt` (or `climb.txt`, `garden.txt`). `.` = empty.
  Legend is in the header of `scripts/level_data.gd` (`=` platform, `O` iron,
  `^` spike, `S/F/J/C` cramps, `P` spawn, `2/3/4` minigames, `5` boss, `a–z`
  dialogs; level 2: `@` bubble, `%` popping bubble, `~` updraft, `N` distraction,
  `6/7/8` minigames, `9` LH wave, `E` summit; the jackpot climb: `!` spring, `$` chip,
  `?` slot box, `0` jackpot row, `E` the top; no letters / minigames there). Keep 25 columns. Minigame / boss /
  wave / summit triggers span the whole row. `Game.LEVELS` maps level id → file.
- **Dialogs**: story dialogs are named `<level><letter>` (0 = prologue in the forest,
  1 cave, 2 forest run, 3 jackpot climb (level id 5), M old meadow, S old summit (level id 3);
  `Game.DIALOG_LEVEL` maps level ids),
  their lines `<level><letter><n>`: `2C3` = level 2, dialog C, line 3 (also the text
  key in `data/i18n/*.json`). Each level starts with its dialog A (not the jackpot climb:
its 3A..3E play on the board, see below). Minigame talk
  (`mg*_start` / `_after` …) is not a story dialog and keeps its own names. Edit them in
  **Developer mode > Dialogs** (`scripts/dev/dialog_editor.gd`, `DialogEditor`:
  lines in SK / EN / PT, speaker, buttons, a fit check, Play, Use in game, Save to repo
  which commits `data/dialogs.json` + `data/i18n/*.json`; local edits in
  `user://dialogs_edit.json`) or by hand (all three languages). Voice =
  `assets/audio/<KEY>.wav` or `voice_overrides`.
- **Characters** (who speaks): `data/characters.json` (`Text.characters`: name per
  language, `portrait` sprite id; `Text.speaker_name`, `Text.portrait_of`). Each
  character has a dialog-avatar sprite in Animations > NPCs (`SpriteArt.extra` for
  ones added in the dialog editor's "New character…"; one frame = a static avatar,
  `SpriteArt.portrait`, a plain disc until it has art).
- **Dialog trigger in the level**: a lowercase letter in a level map starts that
  level's dialog with the letter (`c` in level 2 = `2C`, `Text.dialog_for_letter`).
- **Physics / feel**: constants at the top of `scripts/screens/platformer.gd`
  (gravity, jump, speed). Values match the web build, scaled per frame by `dt60`.
- **Flow** (what happens after a trigger/minigame): `scripts/main.gd`.
- **Input**: actions are created in code in `scripts/autoload/game.gd`. One scheme in every
  level: move ← → (A/D) / D-pad, jump + double jump ↑ / Space / W / 🟡 (X), and the level's
  ability on Shift / 🔴 (B, RB): breathe (cave), focus (`slow_time`, forest run), breathe and,
  once earned, dash (`run`, summit). Kyra always runs (no walk / run key). Texts say
  <KB>Shift</KB><GP>🔴</GP> and <KB>UP / Space</KB><GP>🟡</GP>.

## Conventions

- Don't add nodes to `.tscn` files; build nodes in `_ready()` like the existing scripts.
  New screen = new script with `class_name`, instantiated from `main.gd`.
- GDScript is typed. `:=` on a Variant value is a **compile error** in this
  project (e.g. `var x := dict.value` → use `var x: float = dict.value`;
  use `floorf/absf/minf/maxf/clampf` instead of `floor/abs/min/max/clamp`).
- Textures wider than 8192 px don't load in some browsers — keep
  `process/size_limit=4096` in their `.import` file (see `back.png.import`).
- Coordinates are in the 1066×600 virtual screen (same as the web build).
- Dialog boxes use OpenDyslexic as KeeperDyslexic (`tools/tighten_punctuation.py`: tighter
  letters, punctuation closer to the word; OFL renaming) (`Text.font_dialog` / `font_dialog_bold`); the
  text steps down from 18 px until it fits (`DialogBox.TEXT_SIZES`). The test
  checks every dialog in all languages fits; keep parts short (≈ 3 lines).
- Keep `web-export/` untouched; it is the reference implementation.

## Verify every change

```
tools/test.sh         # imports the project, fails on script errors, runs tests/test_runner.gd
tools/export_web.sh   # builds build/web (serve with: python3 -m http.server -d build/web 8000)
```

`tools/setup_godot.sh` installs Godot 4.4.1 + web templates into the user's cache
(the SessionStart hook runs it automatically). If you change game flow, extend
`tests/test_runner.gd` so the new path is played through. For visual changes, export
and look at the page in Chromium (Playwright is preinstalled in cloud sessions).

The exported page checks for a newer deploy (`tools/web_update_check.js`, injected by `export_web.sh`, compares `version.json` with its own build on load, every minute and when the tab comes back): a chime and a card "New version" listing in a few words the commits newer than the page's build (`version.json` `changes`, the last 40 commit subjects), with a link to `changelog.html` (the log of all commit subjects by day, generated at export; CI checks out 400 commits for it); on the boot / title screens it reloads by itself after 6 s (`window.keeperState`, `main._report_state`; once per new build), elsewhere it waits for the Reload button.

After push, GitHub Actions deploys to `https://bliksa.github.io/keeper/`
(original prototype at `/original/`).

## Animation lab (Developer mode → Animations)

`scripts/dev/anim_lab.gd` previews every player animation (`PlayerArt.ANIMS`: idle,
walk, run, jump, sidejump, doublejump, fall, lookdown, sit, pain, dead, hang) on the
real renderer (`PlayerArt.overrides`).

Besides Kyra, the category tabs (Kyra / Items / Enemies / NPCs) list the sprites of
`scripts/ui/sprite_art.gd` (`SpriteArt.DEFS`: iron, drop, seed, cramp, spike, boss,
bird, distraction, thorn, shadow, estra, portrait_estra / _kyra / _iskra). Most are
drawn in code (`SpriteArt.draw_*` placeholders, empty "original" frame list); a
variant with frames replaces the placeholder wherever the game draws it
(`SpriteArt.draw()` returns false → the caller draws the code art). Per-sprite
fps / size go to `sprites` in `data/anim_variants.json`; ids must not clash with
`PlayerArt.ANIMS`.

The UI has three parts:
- an animation dropdown;
- a variant dropdown with new / duplicate / rename / delete;
- a frame list with pick-from-assets / upload / move / remove per frame, plus
  "Upload frames…" and "From assets…".

The asset browser (`open_assets`) lists repo images via
`ResourceLoader.list_directory` (`assets/images`, `assets/anim_test/**`) plus
uploads in `user://anim_uploads/`. Picked repo files are referenced by `res://`
path, not copied. Space toggles pause in Animation mode. The icon at the top right
of the preview picks a preview background from the same browser (`stage_bg`, kept
in the browser only).

`data/anim_variants.json` has three keys:
- `anims`: anim → variant → [res:// frame paths];
- `in_game`: anim → variant used by the game, applied at start-up by
  `PlayerArt.load_game_defaults()`;
- `settings`: scale, anim_fps, run_rate;
- `sprites`: sprite id → {scale, fps}.

To add PNGs the user sends in chat:

```
tools/add_anim_variant.py run "<variant name>" path/to/*.png [--in-game]
tools/add_anim_variant.py fall "<variant name>" fall*.png
```

The script copies the files into `assets/anim_test/<anim>/<slug>/` and updates the
manifest. Then run `tools/test.sh` and push. Frames are scaled to the same
on-screen height as the originals (85 px × scale). The feet should sit at the same
place in the canvas as in the original frames.

Uploads in the browser go to `user://anim_uploads/` (IndexedDB, local only) until
the user clicks **Save to repo**.

## Developer mode bar

`DevMenu`: the logo (home, back to the menu), tabs Shortcuts / Levels / Animations /
Dialogs, the tab's own tools (`header_tools`) and, right-aligned in every tab, the
same actions from `DevMenu.action_buttons`: test (play), use in game (gamepad), save
to repo (floppy, green). Editors get the box as `top_actions`.

## Saving from the browser (GitHub commits)

`scripts/dev/github_save.gd` (`GitHubSave`) commits files through the GitHub Git
Data API with a fine-grained token the user pastes once (stored in
`user://github_token`, only in that browser).

There are two callers:
- the animation lab commits PNGs plus a merged `data/anim_variants.json`;
- the level editor header commits `data/levels/cave.txt`.

Commits land on the repo's default branch and trigger the deploy. **Run `git pull`
before editing**, because the branch may contain commits made from the browser.
For a local mock API, set `GitHubSave.api_base`, or use `?gh_api=` on the web.

**Team password** (`scripts/dev/dev_access.gd`, `DevAccess`): the token is committed
encrypted with one shared password (`data/dev_access.json`: SHA-256 stretched key,
AES-256-CBC + HMAC). Once it exists, DEV on the boot screen and every "Save to repo"
ask for the password (`DevAccess.password_dialog`, `GitHubSave.token_dialog`), which
decrypts the token into `user://github_token`. Set up / change: Developer mode >
Shortcuts > Team password (`DevAccess.setup_dialog`). The dialog editor, level editor
and animation lab all save through this.


## Backgrounds and the asset browser

`data/backgrounds.json` + `scripts/background_data.gd` (`BackgroundData`): per level
`base` colour, `procedural` (the meadow / summit code-drawn sky), `tint` (cave red
tint + vignette) and parallax `layers` (`image`, `speed`, `scale`, `offset` [x, y],
`opacity`, `repeat`), drawn by `BackgroundData.draw_layers` in `Platformer._draw_bg`
(anchored to `Platformer.bg_origin_for`, the summit starts at the bottom).
`Game.custom_backgrounds` holds "Use in game" overrides; `Platformer.background`
the editor's test-play config.

Level editor > layers icon opens `scripts/dev/background_panel.gd`
(`BackgroundPanel`): preview, layer list and sliders. The editor keeps edits in
`bg_edit` (only changed levels; `_bg_view` = untouched copies), persisted with
`bg_saved` in `user://backgrounds_edit.json`; `build_bg_commit` commits uploaded
images to `assets/backgrounds/<level>-<name>-<hash>.png` (≤ 4096 px) with a
merged `data/backgrounds.json`, and refuses to commit an unreadable image.

`scripts/dev/asset_browser.gd` (`AssetBrowser`) is the shared browser (lab and
editor): `folders()` / `list()` (repo images, `assets/backgrounds`, `anim_test/**`,
uploads in `user://uploads/` and `user://anim_uploads/`), `tex()` (uploads decoded
by signature and scaled to 4096 px), `thumb()`, `bytes_of()` / `file_name()` for
downloads, `store()`; Upload (JS file input / FileDialog / drop), per-tile
download, delete only for `user://uploads/` and not while `in_use` says so.

## Level 2: the forest run

`scripts/screens/forest_runner.gd` (`ForestRunner`, a Node2D screen, not a
Platformer): a pseudo-3D endless runner seen from behind (`project()`: x sideways,
y up, z along the path; `dist` = progress). The course is a **top-down map**,
`data/levels/forest_run.txt` (level editor id 4 = `ForestRunner.LEVEL_ID`, 6 columns:
left side | four paths | right side (`PATHS` = −1.5…1.5 × `LANE`), one row = `ROW_M` m, the bottom row is the
start; `MAP_HEADER` keeps the legend): `R` root, `H` branch, `V` flying notification (an envelope with wings and "!", kind `bird`), `D`/`U` water
drop low/high, `+` sun piece, `<` `>` side trap (thorny vine),
`A` next stage, `a–z` dialog. `build_course()` reads it (`rows`, or
`Game.current_level_rows(4)`).

The sun (HUD top-left where the cave's iron nut is, `SpriteArt.draw_sun`; water = the hydration pill top-right, `draw_water_pill`, where the cave's breath is) has 12 triangular slices; each
`+` fills one (`sun`). Every `SUN_PER_GAME` = 3 pieces `sun_game(n)` → Main opens
mg8 (memory) / mg9 (catch) / mg10 (pairs) and `_back_to_cave` calls `after_minigame()` (next stage
from its start); the 12th piece → `finished` → `runner_end` → `_start_summit`.
`stages` (cut by `A` rows; the map has 4 of 3 pieces each: jumping + water, faster,
flying notifications, fastest + random side traps): speed `STAGE_SPEED[stage]` + `STAGE_RAMP` within the
stage; from `RANDOM_TRAPS_FROM` random side traps (`_random_traps`, new on every
repeat). A stage whose pieces can no longer all be found repeats
(`_check_loop` → `_loop_stage`, queued as soon as its end comes into view: a copy is laid out beyond `dist + VIEW`, nothing in view moves; what already shows of the next stage is run through first and copied after the repeat; `_enter_loop` at the old end moves the missed pieces into the repeat). A hit's lost slice tumbles out of her (`lost_flyers`) and blinks red in the sun (`sun_lost`). Web shortcut `?run=hit` shows it. Four lanes (`lane` = a `PATHS` value, `px`), jump / double jump (`jump()`; the double jump needs two drops, else `water_short` + `short_for`), hits (then `invuln` = `INVULN_TIME` 3 s: she blinks and nothing hits her):
`bump()` (roll back `BUMP_BACK`, not before the stage start; −`HIT_DROPS` and `_lose_slice()`: the stage's last found piece goes back onto the track, never below the last minigame's count), a flying notification in the air =
`carried()` (`CARRY_BACK`); `_reset_behind()` re-arms what she must pass again,
except within `GRACE`. Water: a magazine of 4 drops (`drops`, HUD top-right, `draw_water_pill`) fed by the bar `water` (0–100, the line round the pill fills like the cave's breath ring, `progress_outline`; path drops `D`/`U` add `DROP_WATER`). A jump is free, a double jump costs `DOUBLE_DROPS` = 2, focus (`slow_time`) burns `FOCUS_DRAIN` = 1 drop/s, a hit `HIT_DROPS` = 1; an empty magazine reloads from the bar (`DROP_UNIT` per drop, `RELOAD_TIME`, `_update_magazine`). The map comes from `tools/gen_forest_run.py` (fluid: every obstacle row has `min_gap` rows of reaction time at the stage speed, the free path moves one over; the generator checks it). `jump_to(z)` moves her (and the stage) for tests / the dev menu
("Forest run", "Stage 2", "Stage 3"). Level editor: tool group "Forest run",
`_draw_runner_row/_cell`, test play `_start_runner_test` (minigames skipped).
Level start (from the boss: `main._on_boss_defeated` plays dialog 1D in the arena while the nuts form their ring into the grain; then `_into_forest` waits for the ring to close, the floor is gone and Kyra hops up and over to the middle, then falls, growing towards us (`Platformer.start_exit_fall`, `EXIT_HOP`, `EXIT_GROW`, PlayerArt option `grow`), the camera following, then `_start_runner(..., over_cave = true)` fades the run in over the arena (`start_intro(null, true)`, `Platformer.hide_egg`): when the arena goes, the run takes Kyra over where she was on screen (`Platformer.exit_visual` → `ForestRunner.handoff`) and she falls on onto the path, growing to her size there (`HANDOFF_FALL`, `land_t`) and lands with her back to us, the grain flies to the top-left and opens into the sun (`_draw_grain`, `_draw_intro_hud`), the trees appear from the screen centre (`_intro_k`, `INTRO_TREES`), then `intro_done` → `show_controls` (instead of 2A). Web shortcut `?boss=win` opens the arena with the boss just beaten. Dialogs 2A (start from the dev menu), 2B (notifications, letter b), 2C (side traps, letter c), 2E (end). No seeds in the run.

## Level 3: the jackpot climb (ovulation)

Same `Platformer` with `level_id = Game.CLIMB_ID` (5; `is_climb()`; `is_up()` = the
climb or the old summit: camera target H/2, `bg_origin_for` anchored at the bottom,
checkpoint / `_stand_at_trigger` search below, the procedural `_draw_garden_bg`).
Map `data/levels/climb.txt` (25 columns, P at the bottom, E at the top). Legend: `!`
entity `spring`, `$` `chip`, `?` `slot`, `0` trigger `jackpot` (whole row, a checkpoint),
`~` updraft; E becomes trigger `climb_top` in `setup` (sets `climb_won`). Checkpoints
`LevelData.PROGRESS[5]` = jackpot ×3 + climb_top (`_place_at_checkpoint` takes the n-th
row of a repeated kind, from the bottom; 5 = a few rows below the top). Flow in
`main.gd`: `_runner_done` → 2E → `_start_climb(1)` (no dialog at the start: the climb
never opens the DialogBox and has no minigames); `jackpot` → `Game.checkpoint`;
`climb_top` → 2 s → 3E on the board → `board_dialog_done("3E")` → `reset_run` → title
(`_run_id` guarded). The map has no dialog letters; one painted in the editor plays on
the board (`_hit_trigger`), painted `mg*` / boss / wave / gate triggers do nothing here. Dev menu column "3 · Jackpot climb" (`checkpoint5`), web
`?climb=1` / `?climb=top`. Strings `CLIMB_*`.

Mechanics (all level 5 only, constants at the top of `platformer.gd`):
- **The board** (`BOARD_H` = the dialog box rect at the bottom): drawn by
  `PlatformerHud._draw_board` (dialog-box panel, Estrogenka's portrait, a marquee of
  chasing bulbs, the news ticker `Platformer.ticker` scrolling `CLIMB_TICK_1..8` right →
  left at `TICKER_SPEED`, event lines via `ticker_say()` come next and the ticker hurries;
  the slot reels on its right). Its top edge (`board_y()`) is always a floor (the dialog
  floor code in `_update`). Kyra is on layer 9 above it.
- **Board dialogs** (`board_dialog(id)`, no DialogBox, no buttons, not modal:
  `dialog_open` stays false, play and the rise go on): the node's parts replace the ticker
  (paused meanwhile) in `board_talk` ({id, part, t, dur, speaker, key}): the speaker's
  portrait and name in the avatar slot, the line (`board_line`) wrapped in `BOARD_TEXT` at
  the largest `DialogBox.TEXT_SIZES` size that fits (`board_text_size`), each part for
  `board_read_time` (2.5 s + 0.05 s/char, 3…8 s) with a thin progress line
  (`PlatformerHud._draw_board_talk`), its voice if `Text.voice_file` has one; then
  `board_dialog_done(id)` and the next one from `board_queue`. `board_talking(id)`,
  `board_next()` (tests). The first grant of each power-up in a climb (`grant_power`,
  `powers_explained`, `POWER_DIALOG`) explains it: 3A super jump (+ slot boxes always
  pay), 3B triple, 3C magnet, 3D rocket (the LH surge); 3E = the end. A timed
  power-up's clock stops while its explanation talks or waits on the board, so it never
  runs out mid-explanation; the first box of a climb always pays the super jump (3A
  introduces the boxes). In the climb `_hit_trigger` ignores every trigger except
  `dialog` (→ board), `jackpot` and `climb_top` (no cramp dialog, minigame, wave …). All Estrogenka
  (3E: Kyra too), no buttons. The test checks every 3* line fits the board in all
  languages and both control modes; the dialog editor's fit mark checks the board for
  3* (`DialogEditor.on_board`).
- **Auto-rise** (`_climb_camera`): the camera rises by `rise` (`RISE_START` →
  `RISE_ACCEL` → `RISE_MAX`), follows her up, never scrolls down. It never stops (she
  sits on the board, a board dialog talks …): only `rise_wait` = `RISE_GRACE` at the
  start / a checkpoint (`_board_camera`) and after the top.
- **Caught** (`_caught`): standing on the board (fell, or the edge reached her feet; a
  clamp keeps her above it even on frame spikes, and after the camera moves she is
  snapped onto it, so she rides it up sitting) → x1, `rise` back to `RISE_START`,
  `CLIMB_REST` on the ticker, she sits when idle; floors carried up don't count for the
  streak; a jump leaves any time. No death: `_hurt` only knocks her back, cramps don't
  grab, no breathing.
- **Springs** `!` (`_spring`: `SPRING_FORCE` ≈ 550 px, jumps refilled, BOOST!, `boost_t`
  keeps a released jump key from cutting the flight), **chips** `$` (`_take_chip`: +10),
  **slot boxes** `?` (`_start_slot` → `slot_spin` reels, `SLOT_STOPS`, pays at `SLOT_SPIN`
  via `_pay_slot` → `grant_power` from a shuffled bag `_next_power`: `super_jump` ×1.3,
  `triple` 3 jumps (`_max_jumps`), `magnet` pulls chips in `MAGNET_RANGE`, each
  `POWER_TIME` s in `climb_power`; `rocket` ≈ 900 px now), `~` updrafts.
- **Wins** (`_win`: amount × `climb_mult`): `climb_win`, the multiplier +1 every
  `MULT_FLOORS` floors of a streak (since the last catch, max `MULT_MAX`), a JACKPOT
  (`_jackpot`: +500 ×, banner, `_coin_shower`) every `STREAK_JACKPOT` floors of a streak,
  on each `0` row and (+1000 ×) at the top. Floating `pops`, `banner`, particles `coin` /
  `glint` / `flame`, `_draw_casino_lights` over the dusk→morning sky, `_draw_climb_platform`.
- HUD (`PlatformerHud._draw_climb`): FLOOR top-left with the power-up pills under it,
  the WIN counter rolling up (`_win_shown`) with the multiplier top-centre, the banner.
- Map: `python3 tools/gen_climb.py` (seeded; reads GRAVITY / JUMP_FORCE / MAX_SPEED from
  `platformer.gd` and asserts every row is one normal jump from the one below, and that
  there are no dialog letters and no minigame / boss / wave digits; `--check` checks the
  current file). Editor saves drop its header comment.

## Old level 3: the summit (ovulation; dev menu only)

Reached from the developer menu's OLD / DEPRECATED list (`checkpoint3`) or the old

## Game feel (levels 2 and 3)

`feel()` (level_id ≥ 2) switches on `FEEL_ACCEL` / `FEEL_FRICTION`, coyote time
(`p.coyote`, `COYOTE`), the jump buffer (`p.jump_buffer`, `JUMP_BUFFER`), variable
jump height (releasing `jump` early halves `vy`) and squash / stretch (`p.squash`,
passed to `PlayerArt.draw` as `o.squash`). `_do_jump()` is the one place a jump
starts. The cave keeps the web build's physics.

is built into the site at `/v1/`. Branch `backup/v2-zahrada-hore` holds the first
level-2 draft (the upward garden, now level 3). Tags cannot be pushed from
sessions (403).

## Pause menu

`Esc` / gamepad Start during play (forest, cave, minigames) opens
`scripts/ui/pause_menu.gd`: Continue, Restart game (fresh run from the forest),
Fullscreen on/off, Main menu. It uses `get_tree().paused`; the menu itself runs with
`PROCESS_MODE_ALWAYS`. Async steps in `main.gd` check `_run_id` so a fade
started before a restart can't act on the new run.
